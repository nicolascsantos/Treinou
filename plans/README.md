## Direction findings (not in the plan queue)

These are opportunities to evaluate, not bugs to fix. They are listed here for visibility.

**D1 — RBAC: link Identity users to domain entities**
`ApplicationUser` has a `UserType` enum but no database link to `Teacher` or `Student`. This means authentication works but authorization is meaningless — a logged-in Teacher can modify any Student's data. Link the identity user to the domain entity (e.g., `Teacher.UserId`) and add a policy that checks ownership. Effort: M–L. Requires schema migration.

**D2 — Move `Microsoft.EntityFrameworkCore.InMemory` to test projects only**
The InMemory provider is referenced in `Treinou.Infraestructure.csproj` rather than a test project. This increases the production binary size and signals test infrastructure bleeds into prod. After Plan 006 creates the test projects, remove the InMemory reference from the infrastructure project and add it only to the test projects. Effort: S.

**D3 — Upgrade `Microsoft.AspNetCore.Identity` from 2.3.9 to 10.x**
The infrastructure project references Identity 2.3.9 while the rest of the stack targets .NET 10 / EF Core 10.0.6. This is a significant version gap with security implications. Do this in a dedicated upgrade plan with full regression testing of the auth flow. Effort: M. Risk: HIGH (Identity API surface changes across major versions).

**D4 — Replace `DateTime.Now` with `DateTime.UtcNow` across domain entities**
Multiple entities use `DateTime.Now` (local time) for `CreatedAt`. This breaks consistency for deployments across time zones and complicates sorting/comparison. After Plan 002 lands, audit all `DateTime.Now` usages and convert to `DateTime.UtcNow`. Effort: S. Risk: LOW (no schema change needed).
